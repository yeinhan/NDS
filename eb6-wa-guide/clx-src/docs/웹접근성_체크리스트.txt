* 웹 접근성 체크리스트

프로젝트 내에서 웹 접근성 준수 여부에 대해서 체크해야할 항목들입니다.
심사를 위한 최소한의 체크리스트이며,
웹 접근성 준수가 필요한 프로젝트 내에서는 반드시 확인하시기 바랍니다

1. 접근성 레이블
	⇒ 확인방법
	1-1) 스튜디오 - 접근성 검토모드
	1-2) 브라우저 - checkAccessibilityProperties.module.js 기능 확인 

2. 탭 이동 순서 확인
	⇒ 플로팅을 포함한 모든 영역에 대한 탭 이동 순서 확인 필요
	
3. 퍼블리싱 확인
	⇒ 기본 접근성에 관련한 스타일 확인(명도대비, 콘텐츠 구분 등)
		⨽ 미준수될 경우, 다음 두 가지 방안 선택
			- 기존 스타일을 변경할 수 있도록 기획에 요청
			- 고대비 테마 지원 

4. 웹접근성 모듈 기능 확인 
	⇒ accessibilityProperties.module.js 변수 값 확인
	⇒ accessibility.module.js 기능 확인
	⇒ keyboard-focus.module.js 적용 확인
	⇒ 웹접근성 가이드에서 제시한 defaults.js 적용 확인

5. 로드마스크
	⇒ 루트 앱 인스턴스에 뜨는것을 권장(컨트롤 클릭 후 탭하면 내부 탭 동작함)
	⇒ 로드마스크가 띄워져 있을 때에는 키보드 동작 금지

6. 메시지 다이얼로그
	⇒ 아웃풋 ariaLive=assertive 적용

7. 다이얼로그
	⇒ 모달 적용 (포커스 가두기 위함)
	⇒ autoFocssedTarget, restoreFocus 기능 확인
	⇒ 모달이 두 개 이상 뜨지 않는 것을 권장
 
 8 로드이벤트
 	⇒ 각 화면 로드 시, 내부적으로 포커스 처리하는 것은 지양
 	    (메인 화면에서 내부 화면 로드시 포커스 처리, 최초 로드시 포커스 위치를 일치하기 위함)
 	    ⨽ 그리드init 에서 포커스 처리에 대한 공통 결정 필요(로드 이벤트에서 그리드 조회 할 경우) 

9. 웹접근성 점검 도구
	- 센스리더
	- CCA : 명도대비
	- KWCAG a11y inspector : 컨트롤의 대각선 크기 확인(6mm이상 구현 필요, 확장 프로그램)
	- W3C Validation : 웹 표준 검사 사이트

10. 서브미션
	⇒ util.Submit.send 사용 시, 서브미션 에러 핸들러에서 coverPage 사용 제거
	    ( 서브미션 에러 시 커버페이지가 씌워지지만, tab 이동이 가능 → 공통메시지를 띄우는 방식으로 변경하는 것 권장) 
	    
11. 컨트롤 단축키 안내 페이지 제공
	⇒ eXBuilder6 에서 제공하는 다양한 단축키를 올바르게 사용할 수 있도록, 단축키 페이지를 제공
	   (docs/eXBuilder6_웹접근성_컨트롤가이드_v1.1.pdf  - 4.3. 웹접근성 관련 단축키 확인)
	   (ㄴ 위 문서를 참고하여 만든 clx 예시 : app/com/comGuideWaShortKey.clx)
	   
12. 트리 체크박스
	⇒ showItemCheckBox=true 권장 (트리 컨트롤 가이드 화면참고)
	    

※ 웹접근성 점검 도구는 브라우저의 확장 프로그램으로 제공
※ 내부망에서 확인하기 위해서는 확장프로그램의 별로 설치 파일 필요
